## 0. Before you delete anything

```bash
git clone https://github.com/MrOwaisAbdullah/claude-youtube-editor socialfte
cd socialfte

cd remotion && npm install && npm run gen && npm run studio
```

The repo ships 37 real shots from a published video that render standalone with no
footage. Spend 30 minutes in Studio reading a few of them. That is the fastest way to
learn `remotion/src/lib/` — the motion kit you're about to inherit. Once you've read
them, delete them.

Also read `CLAUDE.md` and `brand.md` before overwriting. The structure of both is worth
copying even though the content isn't.

## 1. The mental model

The source repo is **one long 16:9 talking-head video, edited by an agent**.
SocialFTE is **many short 9:16 posts, generated in batches**.

Those are different products, so you are not adopting the pipeline. You are harvesting
four things out of it:

| What | Why it's worth taking |
|---|---|
| The **brand contract system** | Makes visual consistency a file, not a habit |
| The **Remotion motion kit** | Timing, easing, typography primitives that don't crash |
| The **ffmpeg tool layer** | Tested wrappers you'd otherwise write badly |
| `yt_upload.py` | OAuth + upload + self-verification, already working |

Everything else is either dev-content specific or assumes a single long video.

## 4. The two adaptations worth explaining

### `yt_upload.py` → `publishers/youtube.py`

The source version already does the hard parts: OAuth device flow, resumable upload,
and self-verification — it checks for ghost speech and A/V drift before uploading, then
uploads as a private draft.

Changes needed:

```python
# 1. Shorts requirements
#    - vertical 9:16
#    - ≤ 60 seconds
#    - "#Shorts" in title or description
body["snippet"]["description"] = f"{caption}\n\n#Shorts"

# 2. Read privacy from env instead of hardcoded
body["status"]["privacyStatus"] = os.environ["YOUTUBE_PRIVACY_ON_UPLOAD"]

# 3. Return the video id so the caller can write posts.external_id
return response["id"]

# 4. Drop the "ghost speech" check for posts with no dialogue
#    (keep A/V drift — it still catches broken renders)
```

Keep `yt_upload_SETUP.md`. It walks the Google Cloud console steps you'll need.

### `/packaging` + `gen_thumbnail.py` → `/cover-frames`

The source generates one title × 3 thumbnail images for YouTube's A/B test, using
reference face photos and Gemini.

Yours generates **3 cover-frame candidates for a Reel** — the still that shows in the
grid. No faces, no Gemini image generation. Instead:

```
1. ffmpeg extracts 12 candidate frames across the clip
2. Gemini 2.5 Flash (vision) scores each: is the product fully visible?
   is it in focus? is the composition clean? is there motion blur?
3. Top 3 go to the Discord approval card, you pick one
4. Chosen frame becomes the IG cover / YouTube thumbnail
```

The scoring prompt lives in `.claude/skills/asset-tagging/`. This reuses the frame
extraction from `cutlib.py` and drops the whole Gemini-image-generation dependency.

Note: the source repo's `/packaging` rules were calibrated on a real channel's CTR data,
and it says so — the numbers themselves don't ship. Your version starts uncalibrated too.
After ~30 posts you'll have your own reach data to tune against.
